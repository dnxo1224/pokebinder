# ADR-0001: 도감과 바인더 제작의 분리, 그리고 보관함 폐기

- **상태**: 채택 (2026-08-07)
- **영향 범위**: 정보 구조 전반, `cards` / `binders` 스키마, 바인더 편집기, 적재 파이프라인

## 맥락

서비스가 세 갈래(`카드 검색` / `세트 도감` / `바인더`)로 나뉘어 있었고, 도감의 1차 단위가 **세트**였다.
그런데 세트는 카드를 묶는 여러 기준 중 하나에 불과하다. 포켓몬 도감번호, 아티스트,
카드 종류(트레이너/에너지) 모두 대등한 묶음 축인데 세트만 최상위에 올라가 있어
나머지 축으로는 아예 탐색할 수 없었다.

도감과 바인더의 결합도 문제였다. 도감의 카드마다 **"보관함에 담기"** 버튼이 있고,
담긴 카드는 전역 `card_storage`에 쌓였다가 바인더 편집 모드의 사이드바에서
드래그로 배치되는 구조였다. 이 설계는 두 가지를 강요했다.

1. 바인더가 여러 개일 때, 보관함의 카드가 **어느 바인더용인지 구분되지 않는다.**
   바인더 A를 편집하는데 B용으로 담은 카드까지 전부 사이드바에 뜬다.
2. "어느 바인더에 넣을지"를 **도감에서 탐색하는 시점에** 정해야 한다.
   정작 그 판단에 필요한 맥락(바인더의 빈 칸, 주변 카드와의 배치)은 그때 화면에 없다.

바인더별 보관함을 만드는 안도 검토했으나, 결정 시점을 더 앞당기고 풀을 쪼개
"보관함 간 이동" UI를 새로 요구하게 되어 기각했다.

## 결정

### 1. 서비스를 두 축으로 나눈다

```
홈
├── 도감          — 탐색 전용
└── 바인더 제작   — 목록 → 개별 바인더 → 편집
```

두 축은 **즐겨찾기(찜)** 하나로만 연결된다. 도감에서 카드를 바인더로 직접 보내는 경로는 없다.
바인더는 **자체 검색**으로 카드를 찾아 바로 배치한다.

### 2. 도감의 대분류를 7개로 재편한다

세트를 최상위에서 강등시키고, 대등한 축들을 나란히 놓는다.

| # | 대분류 | 2단 | 3단 |
|---|---|---|---|
| 1 | 즐겨찾기 | — | 찜한 카드 |
| 2 | 카드 세트 | 세트 395 | 카드 |
| 3 | 포켓몬 도감번호 | 종 1,026 | 카드 |
| 4 | 아티스트 | 작가 422 | 카드 |
| 5 | 트레이너 | Supporter / Item / Tool / Stadium / 클래식 (+희귀 2종) | 카드 |
| 6 | 에너지 | Normal / Special | 카드 |
| 7 | etc | — | 카드 661 |

- **언어(GLOBAL/EN/JP)는 대분류보다 상위 필터**이며 도감에서만 쓴다. 바인더는 실물의 거울이므로 언어 혼합을 허용한다.
- 진입 시 **아무것도 출력하지 않는다.** 3만 장을 맥락 없이 쏟지 않기 위해 대분류를 먼저 고르게 한다.
- 검색은 **선택한 대분류 내부**로 한정한다. 카드 이름과 아티스트 이름을 훑는다.
- 탐색 상태는 URL 쿼리에 보존한다 (`/dex?lang=en&cat=set&set=base1`).

**클래식**은 `trainerType`이 없는 트레이너 **615장**이다. Item/Supporter/Stadium 구분이
EX 시대(2003+)에 생긴 개념이라 그 이전 카드에는 존재하지 않는다. 데이터 결손이 아니라
역사적 사실이므로 영구적인 묶음으로 둔다.

적재 후 실측한 트레이너 분포는 아래와 같다. `Rocket's Secret Machine`(5장)과
`Technical Machine`(4장)은 특정 시대에만 쓰인 희귀 타입이라, 별도 묶음으로 노출하지 않고
**기타로 접어 클래식과 함께 둔다.** 에너지는 `energyType`이 없는 18장이 같은 취급을 받는다.

| trainer_type | 장수 |
|---|---|
| Supporter | 1,771 |
| Item | 1,170 |
| (클래식) | 615 |
| Tool | 466 |
| Stadium | 335 |
| Rocket's Secret Machine | 5 |
| Technical Machine | 4 |

**etc**는 포켓몬 카테고리인데 도감번호가 없는 661장이다. 수작업 라벨링 후 소멸할 임시 분류다.

### 3. 보관함(`card_storage`)을 폐기하고 즐겨찾기로 대체한다

- 즐겨찾기는 **Y/N 토글**이다. 같은 카드를 여러 번 담는 수량 개념을 버린다.
- 바인더에 같은 카드를 여러 장 꽂으려면 **검색 목록에서 여러 번 드래그**한다.
- 바인더 사이드바는 **검색창 + 세트 선택 + 언어 칩**으로 구성하고, 즐겨찾기는 그 위의 필터로 얹는다.

### 4. 바인더를 목록/개별로 나눈다

- `/binders` 목록(커버 그리드) → `/binders/[id]` 개별
- **읽기 모드가 기본**(펼침면 감상). 사이드바를 열면 편집 모드로 전환된다.
- 편집 모드도 **양면 + 사이드바**로 간다. 실측 결과 세로가 먼저 제약이 되어
  단면 대비 카드 크기 손실이 없다(3×3 기준 양쪽 다 131px).
  1,199px 이하에서는 가로가 먼저 막히므로 단면으로 자동 전환한다.
- 카드를 빼는 동작은 **사이드바로 드롭**이다. 사이드바 전체에 그림자와 테두리가 생기고
  중앙에 회색 휴지통이 뜬다. 되돌릴 수 없는 동작이므로 실행취소 토스트를 띄운다.
- 커버는 **세트 로고 중에서 고른다**(157개 사용 가능, 전부 EN). 미지정 시 Base Set 로고.
  사용자 파일 업로드는 저장 인프라가 필요해 기각했다.
- 페이지는 기본 10장, 상한 60장. 번호는 10개 단위 블록으로 끊어 보여준다.

### 5. 화면 폭에 따른 편집 모드

| 폭 | 편집 모드 |
|---|---|
| ≥1200px | 양면 + 사이드바 |
| 768–1199px | 단면 + 사이드바 |
| <768px | **차단, 읽기 전용** |

<768px를 막는 이유는 두 가지다. 사이드바가 268px 고정이라 375px 화면에서는
스프레드에 59px밖에 남지 않아 레이아웃이 무너진다. 그리고 **HTML5 드래그앤드롭은
터치 기기에서 동작하지 않으므로**, 폭 문제를 풀어도 카드를 끌 수 없다.
감상(읽기 모드)은 모든 폭에서 동작한다.

## 결과

### 긍정적

- 세트 외의 축(도감번호·아티스트·카드 종류)으로 탐색이 열린다. 데이터는 이미 적재돼 있어
  아티스트 422명은 재적재 없이 바로 쓸 수 있다.
- 도감과 바인더가 분리되어 각자의 목적에 맞게 진화할 수 있다.
- 즐겨찾기가 Y/N이 되면서 목록이 중복 없이 깔끔해진다.
- 바인더 편집 시 감상용 펼침면이 유지된다. 이 앱의 존재 이유가 "배치가 예쁜지 미리 보기"이므로
  제작 중에도 그 시야를 잃지 않는 편이 맞다.

### 부정적

- **직전에 만든 보관함 기능 일체가 폐기된다.** `card_storage` 테이블, `/api/storage`,
  `AddToStorage`, 바인더 사이드바의 보관함 목록, 휴지통, `slots` API의 `unplace` 경로.
- `/sets`, `/sets/[code]`, `/search` 세 페이지와 `SetBrowser`, `CardSearchUI`가 `/dex`로 흡수되며 재작성된다.
- 모바일에서 바인더 편집이 불가능하다는 제약이 명시적으로 굳는다.

### 유지되는 것

바인더 편집기의 뼈대(드래그 배치, 페이지 삽입·삭제 시 슬롯 이동, 스프레드 크기 계산),
디자인 시스템, 적재 파이프라인, 홈 캐러셀은 그대로 살아남는다.

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| 바인더별 보관함 | 결정 시점을 더 앞당기고 풀을 쪼갠다. "보관함 간 이동" UI를 새로 요구한다. |
| 전역 보관함 유지 + "예정 바인더" 태그 | 도감/바인더를 분리하기로 하면서 보관함 자체가 불필요해졌다. |
| 도감 = 포켓몬 종 카탈로그 | 카드 5,678장(18%)이 종을 갖지 않아 트레이너·에너지가 갈 곳을 잃는다. |
| 축 × 카드종류 2층 격자 | "도감번호 × 트레이너"처럼 성립 불가능한 칸이 생긴다. |
| 커버 이미지 사용자 업로드 | 파일 저장 인프라가 새로 필요하다. 세트 로고 선택으로 충분하다. |
| 이미지 없는 카드 필터/정렬 | 한글·일본 데이터를 크롤링해 채울 예정이므로, 지금 트리거를 걸면 나중에 걷어낼 부채가 된다. |

## 보류

`card_group`(언어 통합용 논리 카드) 테이블은 미사용 상태로 존치한다.
한글·일본 데이터를 크롤링해 언어별 이름 매핑을 만들 때 이 자리를 쓴다.
GLOBAL 언어 옵션은 그때까지 단순 합집합으로 동작한다.
